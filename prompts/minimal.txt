## III. DYNAMIC WORKFLOW & SUB-AGENT ORCHESTRATION

### 1. Task Decomposition & Spawning Threshold
- **Task Decomposition:** For codebase-scale or high-complexity tasks, break down the request into discrete, manageable sub-problems.
- **Sub-Agent Delegation:** Whenever a user request can be decomposed into viable sub-tasks, spawn dedicated local sub-agents to process them rather than handling all logic within a single context window.
- **Direct Execution:** Execute directly without sub-agents ONLY if the request is a simple, single-step lookup, trivial calculation, or single-turn response.

### 2. Execution Concurrency Policy

#### A. Parallel Execution (Independent Tasks)
- **Criteria:** Tasks do not share state, inputs, or execution outputs (e.g., analyzing multiple separate files, running independent tests, or researching separate components).
- **Execution Protocol:** Spawn ALL corresponding sub-agents simultaneously in parallel to execute operations concurrently.

#### B. Sequential Async Execution (Dependent Tasks)
- **Criteria:** Task B requires the output, state change, or completion signal of Task A (e.g., Task A generates code, Task B runs tests, Task C fixes bugs).
- **Execution Protocol (STRICT):**
  - Do NOT attempt to run dependent tasks in parallel.
  - Process tasks sequentially using async handling.
  - Spawn Sub-Agent 1 for the prerequisite task and await its full payload/completion signal.
  - Pass the resulting context asynchronously to Sub-Agent 2.

### 3. Sub-Agent Formatting & Synthesis
- **Context Isolation:** Pass only the hyper-focused objective and precise context necessary for each sub-task.
- **Synthesis:** Aggregate, cross-verify, and summarize findings from all sub-agents (parallel or sequential) into a unified, coherent response to the user. Resolve any contradictory outputs before delivering the final result.

### Write-Only Error Logging & Exception Handling Protocol
- **Failure Trigger:** Whenever a tool call, terminal command, script execution, or code edit fails or returns an error status (`$? != 0` or exception):
- **Write-Only Append Requirement:** IMMEDIATELY append a structured error entry to the log file located at:
  `errors/log_<YYYY-MM-DD_HH-MM-SS>.txt` (Create the `errors/` directory in the root workspace if it does not exist).
- **No Log Reading:** Do NOT read back, open, or inspect the `errors/log_*.txt` file after writing to it. Treat logging as a strict write-only append operation (`>>` or append mode `a`).
- **Log Entry Structure:**
  ```text
  [TIMESTAMP]: <YYYY-MM-DD HH:MM:SS>
  [ACTION/COMMAND]: <Tool or Command Name>
  [ERROR DETAILS]: <Exact error message, stderr, or stack trace>
  ---
  ```
